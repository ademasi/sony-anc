# WF-1000XM3 (Sony protocol v1) Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add WF-1000XM3 support by making command encoding and payload parsing protocol-version aware (v1 for XM3, v2 for XM5), with automatic version detection from the init-reply length.

**Architecture:** Introduce `ProtocolVersion { V1, V2 }` in the library and thread it through `build_command(cmd, seq, version)` and `parse_payload(bytes, msg_type, version)`. The framing layer (`frame_parser.rs`, `lib.rs` constants, `Init`/`Ack`) is byte-identical across versions and stays untouched. The unified `Command`/`Payload` enums are unchanged so the CLI and watch loop don't care about version. The CLI detects the version from the 4-vs-8-byte init reply during `connect`, with a `--model`/env override.

**Tech Stack:** Rust 2024, tokio, bluer, clap, thiserror, anyhow.

**Ground truth:** All v1 byte values come from `scratchpad/xm3-v1-protocol.md` (extracted verbatim from Gadgetbridge's `SonyProtocolImplV1` + its 40+ golden test vectors).

            ProtocolVersion::V2 => self as u8,

    /// comparison against Gadgetbridge's golden request vectors.
    fn v1_payload(cmd: Command) -> Vec<u8> {
        let frame = build_command(&cmd, 0, ProtocolVersion::V1).unwrap();
        let mut parser = FrameParser::new();
        match parser.parse(&frame) {

            _ => panic!("frame did not parse"),
